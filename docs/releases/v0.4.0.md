# v0.4.0 — Versioned Identity & Migration Safety

Resolve the identity-framing weakness tracked in #11 without silently changing
existing observation IDs, lineage IDs, stored evidence, or audit behavior.

## Highlights

- Opt-in `instrument_key_v2`, `build_observation_v2`, and `build_lineage_v2`.
- Versioned, domain-separated SHA-256 inputs with counted, length-prefixed fields.
- V2 record construction checks that declared IDs match their evidence.
- Read-only `plan_observation_migration` with frozen per-row mappings; ambiguous
  legacy IDs, mismatched evidence, and over-limit inputs fail without a partial plan.
- Explicit storage/foreign-key migration guidance and a synthetic executable example.
- Regression tests reproduce v1 ambiguities, pin legacy outputs, and verify v2
  framing against fixed vectors and a separately written specification oracle.
- Installed-wheel checks exercise the new identity/migration example alongside
  existing CSV/JSON commands and legacy APIs on the existing Linux/Windows matrix.

## Compatibility and limitations

All 30 previous exports remain, with six new identity/migration exports. Existing
v1 builders retain their outputs and limitations; select v2 explicitly for new
identity-sensitive code. Namespaced v2 strings are longer than 64 characters.
Record field sets, CLI exit codes, JSON schema 1.0, and session audit behavior stay
unchanged. Observation payload serialization is unchanged; IDs describe stored
bytes, not original Python types. Audit timestamps remain outside fingerprints.

No records, source payloads, references, or databases are automatically rewritten.
The planner detects conflicts only within its supplied scope; global reconciliation
and transactional application remain the integrator's responsibility. Hashes are
not signatures, authenticity proofs, or evidence of an external security audit.
No provider integration, private data, strategy, runtime dependency, PyPI publishing,
or OSS application submission is introduced.

See `docs/IDENTITY.md` and `examples/migrate_identities.py`.
