# v0.2.0 — Session-aware Dataset Audit

Audit historical bar datasets against explicit expected sessions without a broker
SDK, exchange-calendar dependency, network feed, or trading logic.

## Highlights

- Half-open, UTC-normalized `ValidationWindow` grids supplied by the caller.
- `audit_bars` and immutable dataset, instrument, and window reports.
- Exact missing start timestamps, including leading/trailing holes and empty windows.
- Separate raw observations, unique covered slots, missing slots, and duplicate counts.
- Outside-window, misalignment, duration, and conflicting-duplicate findings.
- Explicit ERROR/WARNING policy; severity overrides never change coverage counts.
- DST fold/offset regression tests and protection against unbounded expected-grid expansion.
- Fully synthetic two-session example exercised against installed wheels.

## Correctness and compatibility

All 0.1.0 root exports and the two list-returning validation entry points remain.
`ValidationIssue` gains optional severity/context fields. Serializers that assumed
exactly three dataclass fields must account for the new fields.

Direct Bar validation now reports NaN, Infinity, and non-Decimal numeric types
before comparisons. Coverage remains a measure of presence, not price correctness;
a complete but invalid dataset is not reported as valid under the default policy.

## Verification and boundaries

CI covers Python 3.11, 3.12, and 3.13: lint, strict typing, tests, builds, and clean
wheel installation with legacy and session-audit smoke paths. Existing identity
and correction implementations are unchanged. No provider SDK, private data,
production integration, recovery framework, trading feature, or PyPI publishing
workflow is introduced.
